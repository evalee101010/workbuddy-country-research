# 海外 Cowork 类产品宏观市场研究执行方案

> 文档状态：已确认，可作为第一阶段研究执行基线  
> 版本：v1.0  
> 日期：2026-09-03  
> 研究阶段：宏观研究，不进入我方制胜能力、产品路线与首发市场决策

## 一、研究目标

建立一份相对中立、可复查、可持续更新的海外 Cowork 类产品市场底图，用于回答：

1. 全球 Cowork、AI 工作代理及其替代品正在形成哪些产品类型？
2. 哪些国家和地区具备较大的知识工作者基础、较高的 AI 与数字化成熟度及较强的潜在商业化条件？
3. 各国公开网络中，正在出现哪些高频工作痛点、现有替代方案和付费信号？
4. 哪些市场值得进入下一阶段的用户、产品与本地化研究？

本阶段不直接决定首发国家，也不讨论团队自身的渠道、产品、模型、合作伙伴或基础设施优势。

## 二、研究总流程

```text
阶段 A：研究范围定义
  1. Cowork 品类与竞品反馈范围
  2. 国家全集与深度反馈国家
                ↓
阶段 B：两条研究线并行
  B1. 宏观基本面研究（原计划 3、4、6）
      ├─ 经济、就业和数字化基本面
      ├─ AI 与 Agent 成熟度
      └─ 产品供给与竞争结构

  B2. 公开用户需求信号收集（原计划 5）
      ├─ 竞品反馈库
      └─ 国家需求库
                ↓
阶段 C：政策与结构性进入门槛
                ↓
阶段 D：指标标准化、市场分群与综合评分
                ↓
输出：8–12 个下一阶段研究候选市场
```

## 三、阶段边界

### 本阶段纳入

- 全球 Cowork、通用 Agent、办公套件 Agent、AI 自动化与相邻产品的品类结构。
- 各国经济规模、收入、就业、知识工作者、企业和数字化基本面。
- 企业与消费者的 AI 使用、Agent 使用及相关需求增长。
- 搜索、访问、下载、评论、社区讨论和替代方案等公开信号。
- 竞争密度、主要产品类型、价格带和供给结构。
- 数据隐私、数据跨境、支付、语言和产品可用性等结构性门槛。
- 市场的绝对规模、人均成熟度和增长速度。

### 本阶段暂不纳入

- 我方制胜能力或 Right to Win。
- 我方已有渠道、合作伙伴、云节点、客户资源和团队能力。
- 首发国家、最终 ICP 或具体产品定位。
- 产品功能优先级、模型选择和本地化解决方案。
- 具体广告投放、销售组织、CAC 和 GTM 方案。
- 对收入、转化率和 LTV 的过早预测。

## 四、Cowork 品类定义

本研究中的 Cowork 类产品定义为：

> 面向非技术或泛知识工作者，用户能够通过自然语言委派多步骤工作任务，产品可以调用文件、浏览器、办公软件或外部系统，并交付可使用结果或执行实际动作的 AI 工作代理。

一个产品满足以下五项中的四项，即进入核心竞品池：

1. 接受完整任务，而不只是回答问题。
2. 能规划并执行多个步骤。
3. 能访问文件、浏览器、办公软件或外部应用。
4. 能产生可交付物或执行实际动作。
5. 普通工作者无需写代码即可使用。

## 五、竞品反馈研究范围

### A 层：直接竞品

完整采集产品反馈，并作为 Cowork 类产品核心问题的主要证据。

| 产品 | 纳入原因 | 重点观察 |
|---|---|---|
| Claude Cowork | 文件、浏览器、连接器、Skill、插件及角色化工作流与研究对象最接近 | 任务成功、本地文件、权限、配置、价格、可靠性 |
| ChatGPT agent | 面向非技术用户执行浏览器和多步骤任务 | 接管与确认、任务中断、速度、配额、跨设备体验 |
| Manus | 通用任务代理，覆盖研究、文档、Slides、Mail 和浏览器操作 | 复杂任务质量、等待时间、积分、成品质量 |
| Genspark AI Workspace / Super Agent | 从通用 Agent 扩展为包含记忆、邮件、内容和团队协作的工作空间 | 多 Agent 协作、记忆、文档和团队工作 |
| Perplexity Comet / Computer | 浏览器内研究、网页操作和较长任务执行 | 网页成功率、权限、配额、跨标签页稳定性 |
| Work Buddy | 本机执行、远程调度和非技术办公场景 | 东南亚、本地电脑、模板、电商与小团队反馈 |

### B 层：办公套件内置 Agent

重点研究其对 Cowork 需求的替代，以及原生工作上下文是否形成明显优势。

| 产品 | 研究价值 |
|---|---|
| Microsoft 365 Copilot Workflows / Agents | 用户是否更愿意在 Outlook、Teams、SharePoint 等原有环境内完成工作 |
| Google Workspace Studio / Gemini | Gmail、Drive、Docs、Sheets 的原生上下文和企业分发优势 |
| Notion Agents | 团队知识、权限、定时任务、可追溯操作和多人协作 |
| Zapier AI / Agents | 跨应用连接广度、自动化可靠性、配置成本和运行历史 |

### C 层：无代码 Agent 与自动化工具

抽样采集，重点研究用户为什么愿意搭建工作流，以及为什么无法持续使用。

- Gumloop
- Lindy
- Relay.app
- Make
- n8n
- Power Automate

观察重点：

- 配置和学习门槛。
- 模板能否降低首次使用成本。
- 运行稳定性及错误恢复。
- 积分、Token 和不可预测成本。
- 从个人使用升级为团队使用的路径。

### D 层：能力参照，不进入核心用户反馈统计

- Cursor、Claude Code、GitHub Copilot、Trae 等开发者 Agent。
- UiPath 等传统大型 RPA。
- 纯聊天产品。
- 单功能写作、翻译、会议纪要工具。
- 尚无公开用户或只停留在 Demo 阶段的产品。

开发者产品的反馈只能辅助研究 Agent 能力、信任、计费和交互，不用于推断普通办公用户需求。

### 动态纳入规则

研究过程中发现新产品时，先按五项核心标准判断：

- 满足四至五项：进入 A 层候选，经复核后补充采集。
- 满足两至三项，但争夺相同任务：进入 B 或 C 层。
- 只覆盖单一能力或主要面向开发者：进入 D 层。
- 无公开可验证产品或用户：记录在观察清单，不进入统计。

## 六、反馈采集口径

### 时间范围

- 主要观察期：2025-09-01 至 2026-09-30。
- 新发布产品：从正式发布或公开测试之日起采集。
- 必要时补充更早反馈，用于理解某项问题是否长期存在。
- 每条数据保存原始发布日期和抓取日期。

### 重点编码主题

1. 用户原本要完成什么工作任务。
2. 首次使用是否顺利。
3. 是否真正完成端到端工作。
4. 失败发生在哪一步。
5. 需要多少人工纠正或接管。
6. 用户是否愿意授权文件、浏览器和账号。
7. 速度、价格、积分和配额是否可接受。
8. 用户为什么持续使用、退订或迁移。
9. 用户最终换回了什么工具、人工流程或组合方案。

### 有效反馈来源

优先级由高到低：

1. 应用商店和浏览器扩展商店的真实评论。
2. 产品官方论坛、帮助社区和 GitHub Issues。
3. Reddit、Hacker News 等包含具体使用过程的帖子。
4. G2、Capterra、Trustpilot 等评论平台中的详细评论。
5. Product Hunt 评论。
6. YouTube 实测视频下的用户评论。
7. 当地语言论坛和行业社区。

### 不作为用户反馈的内容

- 产品官网客户证言。
- 公司自己发布的案例。
- 纯新闻转载。
- SEO 工具榜单。
- 联盟营销文章。
- 未描述实际使用的一句话好评或情绪表达。

上述内容可以用于确认产品定位、发布日期和功能，但不能计入用户需求与满意度统计。

### 地域归因规则

满足下列条件之一时，才可以把反馈归到具体国家：

1. 来自当地应用商店、国家域名或国家版产品页面。
2. 来自明确的本地论坛、行业社区或地区 subreddit。
3. 用户明确陈述所在国家或经营地区。
4. 内容出现可验证的当地支付、税务、法规、软件或工作环境。

地域置信度分为：

- `high`：来源或用户明确标识国家。
- `medium`：有两个以上当地信息交叉支持。
- `low`：仅由语言或单一间接线索推断。
- `unknown`：没有可靠地域依据。

仅凭语言得到的地区判断最多标为 `low`，不能作为国家级定量结论的主要依据。

## 八、两套公开语料库

### 竞品反馈库

以产品为采样中心，用于回答：

> 现有 Cowork、办公 Agent 与自动化产品在哪些任务、体验、价格、信任和可靠性方面没有满足用户？

特点：

- 允许国家未知。
- 重视详细任务、失败过程和迁移原因。
- A 层产品完整采集，B 层按替代任务采集，C 层抽样。
- 不强求每个竞品在每个国家都有相同样本量。

### 国家需求库

以国家、当地语言和工作问题为采样中心，用于回答：

> 各国用户正在抱怨哪些工作问题、使用什么替代方案，以及是否已经为解决问题付费？

特点：

- 帖子不需要提及 Cowork 或 Agent。
- 查询任务、工作问题、人工流程和替代工具，而不只查询产品名。
- 第一梯队 10 国分别设置最低样本目标。
- 本地语言和英语查询分开保存。

### 两库连接方式

后续通过以下字段连接，而不是通过个人身份连接：

- `job_to_be_done`
- `user_role`
- `input_or_connected_tools`
- `failure_stage`
- `current_alternative`
- `pricing_or_usage_limit`
- `country_or_region`

不收集非研究所需的个人身份信息。

## 九、并行研究线 B1：宏观基本面、AI 成熟度与竞争结构

### B1.1 经济、就业和数字化基本面

每个宏观国家至少收集：

- 总人口和劳动年龄人口。
- GDP、GDP PPP 和人均 GDP。
- 服务业增加值与服务业就业占比。
- 管理、专业、技术支持、文职和销售等知识工作岗位规模。
- 企业总量、SMB 占比和雇员规模结构。
- 自由职业者、个体经营者或平台劳动者规模，若有可靠数据。
- 固定宽带、移动互联网和互联网普及率。
- 个人电脑、桌面操作系统及主要办公套件使用代理指标。
- 云服务、电子商务和数字支付采用情况。

主要来源优先级：

1. World Bank、ILO、OECD、Eurostat、ITU。
2. 国家统计局和政府数字经济报告。
3. 公开的一方平台数据。
4. 有方法说明的第三方估算。

### B1.2 AI 与 Agent 成熟度

收集：

- 企业 AI 使用率及三年增长。
- 生成式 AI 的消费者或工作场景使用率。
- Claude、ChatGPT、Gemini 等产品的地区使用代理指标。
- AI 搜索、Agent、工作流自动化等关键词的相对趋势。
- AI 相关就业、技能与培训需求。
- 企业从试用进入规模部署的比例或代理指标。
- Agent 相关产品的可用国家、语言和平台覆盖。

注意：

- 企业 AI 采用率不能与某个消费产品的地区使用份额直接合并。
- Google Trends 等相对指数不能当成绝对用户规模。
- 产品自身发布的数据需要标明产品样本偏差。

### B1.3 产品供给和竞争结构

收集：

- 每个品类的主要产品和活跃产品数量。
- 产品面向个人、SMB 或企业的定位。
- 定价模式：席位、订阅、积分、按运行或企业合同。
- 支持的语言、国家、桌面系统和办公套件。
- 公开访问量、下载量、评论量及增长代理指标。
- 市场集中度和头部产品份额代理指标。
- 产品进入、退出、并购及重大版本变化。
- 各国家中本土产品与全球产品的相对可见度。

## 十、并行研究线 B2：公开用户需求信号

### B2.1 查询主题

每个第一梯队国家建立英语和本地语言查询词表，至少覆盖：

- 重复文件、表格、报告和后台任务。
- 跨应用复制、整理、同步和提交。
- 批量处理、信息抽取、网页研究和数据录入。
- 电商、销售、市场、行政、HR、财务和专业服务工作。
- “花费很长时间”“手工完成”“希望自动化”等问题表达。
- “替代某产品”“太贵”“额度不足”“不可靠”“隐私风险”等迁移表达。
- 雇佣助理、外包或购买多个软件完成同一工作。

### B2.2 第一轮目标

- 每个第一梯队国家建立独立来源清单和双语查询词表。
- 每个国家优先获得至少 100 条高相关、可编码的需求证据。
- 单一平台的证据原则上不超过该国家有效样本的 40%。
- 单一产品的反馈不能代表整个 Cowork 品类。
- 详细长反馈优先于大量缺乏上下文的短评价。

样本目标是研究执行基线，不是统计显著性承诺；若某国家公开数据明显不足，必须记录缺口而不是用低质量样本填满。

### B2.3 初步分析输出

- 高频工作问题排行榜。
- 任务发生频率和当前解决成本。
- 用户使用的人工、软件和组合式替代方案。
- 首次使用、任务中断和结果校验痛点。
- 价格、配额和付费相关信号。
- 隐私、权限和信任问题。
- 各国共同问题与当地特有问题。

## 十一、阶段 C：政策与结构性进入门槛

在两条并行研究线形成初步结论后，再统一研究：

- 隐私和个人数据处理制度。
- 跨境数据传输及数据驻留要求。
- AI 产品透明度、风险管理和责任要求。
- 自动化操作、平台账户和敏感行业限制。
- 产品、模型、支付和应用商店的地区可用性。
- 企业采购和安全认证的一般门槛。
- 语言数量、语言分布和本地软件生态碎片度。

政策结论必须标注生效日期、适用主体和法律状态；草案、行业建议与生效法规分开记录。

## 十二、阶段 D：市场分群与综合评分

宏观阶段只评价市场本身，不加入我方资源和能力。

| 维度 | 权重 | 示例指标 |
|---|---:|---|
| 知识工作市场规模 | 20 | 知识工作者、服务业就业、SMB 和自由职业者规模 |
| AI 与数字化成熟度 | 20 | 企业 AI、云服务、办公数字化和生成式 AI 使用 |
| 需求强度与增速 | 20 | 搜索、下载、访问、讨论和三年增长 |
| 商业化环境 | 15 | 人均收入、软件支出、数字支付和同类价格 |
| 竞争结构 | 15 | 竞争数量、头部集中、用户评价和供给空白 |
| 结构性进入门槛 | 10 | 监管、数据跨境、语言、支付和基础设施 |

### 三个并列视角

综合分之外，必须分别保留：

- 绝对规模：潜在市场有多大。
- 人均强度：当地采用是否深入。
- 增长速度：市场是否正在快速形成。

不以单一综合分机械决定市场优先级。最终先形成市场分群，再从每类中选择代表性国家进入下一阶段。

### 敏感性分析

- 至少使用三组权重重新计算排名。
- 检查前 10 名是否对单一指标或权重高度敏感。
- 分别计算包含与不包含缺失值估算的结果。
- 大国与小型高成熟市场分开比较。
- 竞争强度既作为需求成熟信号，也作为供给压力，避免简单反向计分。

## 十三、Work Buddy 访谈的使用方式

Work Buddy 海外增长策略访谈仅进入“待验证假设库”，不直接进入宏观评分。

| 访谈观点 | 宏观阶段验证方式 |
|---|---|
| 东南亚非技术用户竞争较少 | 比较各国非开发者 AI 产品供给、搜索和评论结构 |
| 印尼电商场景需求强 | 比较数字商户、电商就业、任务搜索和社区问题 |
| 新加坡适合小团队 B 端 | 比较 SMB 数字化、AI 采用、软件支出和企业密度 |
| 欧美市场过度竞争 | 比较产品数量、流量集中、评论增长和关键词竞争 |
| 日韩渠道和本地化壁垒高 | 比较本土软件份额、语言结构、采购方式和当地产品供给 |
| 本机执行是关键需求 | 比较桌面端、远程工作和相关问题讨论量 |

执行规则：

1. 国家宏观排名完成前，不使用访谈中的 P0、P1、P2 排序作为评分输入。
2. 排名完成后再叠加访谈，记录一致、矛盾和无法验证的部分。
3. 访谈中的 CAC、转化率、留存和预算数字在没有原始数据前不进入模型。
4. 将 Work Buddy 视为一个竞品和案例，而不是行业代表。

访谈来源：`文字记录：Work Buddy海外增长策略访谈 2026年8月27日.md`。

## 十四、数据质量规则

1. 每个关键判断原则上至少由两类独立数据支持。
2. 官方统计优先，其次是一方平台数据，再其次是有方法说明的第三方数据。
3. 每项数据记录统计年份、发布日期、单位、覆盖范围、定义和链接。
4. 绝对值、人均值和增长率分开保存。
5. 直接指标和代理指标分开标识。
6. 缺失数据明确标记，不用主观估值强行填补。
7. 不把搜索热度、讨论量或单个平台用户份额直接等同于市场规模。
8. 研究者的解释与原始观察分字段保存。
9. 本地语言材料保留原文，同时保存中文或英文摘要。
10. 使用官方 API、开放数据、RSS 和 sitemap 优先于网页抓取。
11. 遵守平台条款、robots.txt、访问频率和个人数据要求。
12. 不收集与研究无关的个人身份信息。

## 十六、阶段门槛

### 进入并行研究线前

- Cowork 定义、竞品分层和国家范围已确认。
- 数据字段、来源优先级和地域归因规则已统一。

### 进入政策研究前

- 39 国宏观主表已形成可比较的第一版。
- 第一梯队 10 国均有独立需求样本或明确的数据缺口记录。
- 主要竞品的反馈来源和产品变化已覆盖。

### 进入综合评分前

- 主要指标完成定义和标准化。
- 关键结论完成至少两类数据交叉验证。
- 缺失值、代理指标和低置信度国家已标记。

### 宏观阶段结束条件

- 得到稳定的市场分群。
- 形成 8–12 国研究候选池。
- 明确候选市场入选原因和主要不确定性。
- 不输出我方首发国家或产品方案。

## 十八、变更与反向调整机制

本方案是执行基线，不是不可修改的结论。后续出现以下情况时，可返回本文件调整：

- 新产品满足核心 Cowork 定义并获得显著用户采用。
- 某一竞品发生重大合并、转型或停止服务。
- 第一梯队国家无法获得足够可靠的公开反馈。
- 某个第二梯队市场出现异常强的需求或增长信号。
- 指标定义无法跨国比较或对排名产生明显偏差。
- 法规、产品可用性或数据源发生重大变化。

每次调整需要在文末变更记录中说明：

```text
日期
调整内容
调整原因
影响的数据或结论
是否需要重跑历史数据
```
