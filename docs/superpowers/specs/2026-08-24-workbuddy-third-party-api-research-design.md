# WorkBuddy 第三方模型 API 产品优化研究页设计

## 目标

创建一个单页、可直接编辑的中文研究型 HTML 页面，系统说明没有自有模型的 WorkBuddy 类产品如何通过第三方模型 API 实现质量、延迟、成本与可靠性的产品侧优化。

第一版用于个人研究和内容迭代，不包含账号、多用户、服务端数据库或在线协作。数据结构避免依赖单一用户身份，便于后续迁移到云端多人共享。

## 核心体验

- 打开页面即可阅读完整研究报告。
- 点击正文进入直接编辑状态，不切换到代码或 Markdown 编辑器。
- 编辑内容自动保存到当前浏览器，刷新后恢复。
- 页面显示最近保存时间与保存状态。
- 可将当前版本导出为独立 HTML 文件。
- 可恢复内置的默认研究内容；恢复前必须确认。

## 页面结构

### 顶部研究概览

- 标题：WorkBuddy 第三方模型 API 产品优化研究
- 适用前提：无自有模型、依赖多家第三方 API
- 核心结论与建议架构
- 最后保存时间和本地保存说明

### 章节导航

目录固定展示研究章节，点击后定位到对应内容。章节包括：

1. 研究结论与优先级
2. 产品与模型服务的责任边界
3. 第三方模型接入层
4. 上下文与任务状态管理
5. Prompt Cache 与稳定前缀
6. 模型路由与自动升级
7. 工具调用与 Agent 循环控制
8. 实时任务、后台任务与并发
9. 超时、重试、降级与任务恢复
10. 成本治理与配额设计
11. 数据安全、隐私和供应商边界
12. 指标、实验与验收体系
13. 分阶段产品路线图
14. 中文与英文官方资料库

### 正文研究区

正文采用具有阅读层级的研究报告布局，包含：

- 关键判断
- 产品机制
- 推荐流程
- 反例与常见误区
- 产品需求或配置项
- 建议指标
- 第一阶段与后续阶段的优先级

正文所有文字允许直接编辑。章节标题保留稳定的锚点标识，以保证目录导航在文字修改后仍然有效。

### 底部操作区

- 保存状态提示
- 导出 HTML
- 恢复默认内容
- 本地数据说明

## 内容原则

- 明确区分 WorkBuddy 产品层可控制的能力与模型供应商负责的底层推理能力。
- 不把“减少 Token”当作唯一目标；主要目标为每个成功任务的综合成本、任务成功率、首字延迟和总完成时间。
- 每项建议都说明适用场景、实现方式、产品交互和监控指标。
- 优先引用 OpenAI、Anthropic、Google、阿里云、火山引擎、腾讯云及主流 Agent 框架的官方资料。
- 中文与英文资料分组展示，链接标注主题、语言和适用范围。
- 对会随时间变化的价格、限制和保留政策不写死结论，提示以供应商最新文档为准。

## 本地数据模型

第一版只保存一个研究文档：

```text
ResearchDocument
├── schemaVersion
├── documentId
├── title
├── htmlContent
├── updatedAt
└── revision
```

使用浏览器本地存储保存。`schemaVersion`、`documentId` 和 `revision` 为后续云端同步、版本迁移和冲突处理预留。

## 交互与状态

- 页面加载时优先读取本地版本；没有本地版本时使用内置默认内容。
- 用户输入后短暂延迟再保存，避免每次按键都写入存储。
- 保存中、已保存和保存失败有清晰状态。
- 导出 HTML 时包含当前编辑后的正文和必要样式，不依赖本地存储才能阅读。
- 恢复默认内容会覆盖当前本地版本，必须经过确认。
- 外部文档链接在新标签页打开。

## 视觉方向

采用专业研究备忘录风格：浅色纸张背景、深灰正文、蓝绿色强调色，优先保证长文阅读、信息层级和链接辨识度。桌面端采用目录与正文双栏结构；窄屏设备将目录折叠为顶部导航。

不使用装饰性图片。架构关系以 CSS 卡片、流程和表格表达，避免为简单内容增加视觉噪声。

## 错误处理

- 本地存储不可用或容量不足时，提示用户立即导出备份，页面编辑本身继续可用。
- 导出失败时保留当前内容，不改变本地版本。
- 外部文档链接失效不会影响正文阅读。
- 页面不发起第三方模型调用，因此不需要在第一版处理 API 密钥。

## 验收标准

- 首屏明确说明研究主题、适用前提和核心结论。
- 14 个研究章节内容完整且层级清晰。
- 正文能够直接编辑，并在刷新后恢复。
- 保存状态与最近更新时间准确显示。
- 目录可以定位到所有章节。
- 导出的 HTML 能独立打开并包含编辑后的内容。
- 恢复默认内容前出现确认提示。
- 中文与英文官方资料链接可访问，且说明来源与用途。
- 桌面端和移动端均可阅读和编辑。
- 页面构建无阻塞错误，关键交互通过手动验证。

## 第一版明确不做

- 用户登录和权限管理
- 云端数据库与多人实时协作
- 评论、批注线程与多人光标
- 服务端版本历史与冲突合并
- 在线调用模型或自动抓取文档
- 富文本图片上传与附件管理

这些能力在后续云端版本中，根据真实协作需求单独设计。
